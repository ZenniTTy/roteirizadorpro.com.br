### Implementation

- **`scripts/server-bootstrap.sh`** — idempotent first-run on the droplet. Takes the SSH public key as `$1`; runs as root once. Codifies the 9 manual steps in `docs/07-INFRA.md` (sudo user, SSH hardening via drop-in at `/etc/ssh/sshd_config.d/`, UFW, fail2ban with sshd jail, hostname/timezone/unattended-upgrades, Docker Engine modern repo, `/opt/roteirizador/` tree). Each section detects already-applied state and skips rather than overwriting. Prints a closing summary with next-step commands. Validated with `bash -n` (syntax) and `chmod +x`.
- **`scripts/backup-postgres.sh`** — `docker exec roteirizador-postgres pg_dump --clean --if-exists --no-owner --no-acl | gzip --best`, timestamped UTC, output to `/opt/roteirizador/backups/`, rotates `${RETENTION_DAYS:-30}` days. Cron sample in the script header. All knobs env-overridable.
- **`scripts/rsync-graph-cache.sh`** — laptop → droplet wrapper. Verifies the local cache is non-empty, computes byte sizes, rsync `--delete --progress` to `/opt/roteirizador/data/graphhopper/`. Also pushes the source PBF (optional, for on-droplet rebuild capability post-resize). Single positional arg `<user>@<host>`.
- **`infra/nginx/api.roteirizadorpro.com.br.conf`** — pre-Certbot HTTP-only template. `proxy_pass http://127.0.0.1:3000`, full X-Forwarded-* set, gzip on JSON, conservative timeouts (5s connect / 30s send+read), `/.` deny rule for hidden files. Certbot's `--nginx` plugin will add the 443 server block + 80→443 redirect in place — that's why the SSL block isn't pre-baked.
- **`infra/systemd/roteirizador-backend.service`** — Fastify as a systemd unit. `User=roteirizador`, `WorkingDirectory=apps/backend`, `EnvironmentFile=/opt/roteirizador/compose/.env`, `ExecStart=/usr/local/bin/bun run start`, `Restart=on-failure`, journal logging. Modest hardening: `NoNewPrivileges`, `PrivateTmp`, `ProtectSystem=strict`, `ProtectHome=read-only`, `ReadWritePaths=/opt/roteirizador/logs`.
- **`infra/docker-compose.yml`** — made Postgres credentials env-driven via `${POSTGRES_USER:-roteirizador}` / `${POSTGRES_PASSWORD:-roteirizador}` / `${POSTGRES_DB:-roteirizador}`. Dev keeps the loopback default (no breaking change); production overrides from `/opt/roteirizador/compose/.env`. `pg_isready` healthcheck threaded through with the same substitution. `docker compose config --quiet` validates clean.
- **`docs/07-INFRA.md`** — appended a "Production .env template" section with the full env file content + a dev-vs-prod diff table. Updated "Secrets Inventory" to point to `/opt/roteirizador/compose/.env` (the actual storage location) instead of the placeholder `/opt/roteirizador/certs/.env`. The original plan was a separate `.env.production.example` file but the project's PreToolUse hook (installed in session 02) blocks `.env*` writes except `.env.example`; the hook itself suggested using `docs/07-INFRA.md` and that's the cleaner home for the doc anyway.
- **`docs/INSTALL.md`** — 10-section runbook spanning §1 server bootstrap → §10 acceptance verification, with the full external-smoke-test commands for the four Workana criteria. Cross-references every script + the systemd unit + the Nginx config. Includes a directory-layout map + services map + common-operations cheatsheet (tail logs, restart, manual backup/restore, fail2ban check, Certbot renew).

## Decisions Made

1. **Backend runs as a systemd unit on the host, not inside docker-compose.** The existing local-dev pattern is backend-on-host (`bun run dev`), and dockerizing for production means authoring a Dockerfile + image build pipeline + volume mounts for JWT keys — extra complexity that doesn't pay back inside M1's 18-day window. Post-M1 we may dockerize for parity. Documented in `docs/INSTALL.md` §5 and `infra/systemd/roteirizador-backend.service`.
2. **Postgres credentials via env-substitution in `docker-compose.yml`, not a separate prod compose file.** `${POSTGRES_PASSWORD:-roteirizador}` keeps dev working with the existing loopback triple while letting production `.env` override. A `docker-compose.prod.yml` overlay was considered but adds operational surface for one variable.
3. **Production env template lives in `docs/07-INFRA.md`, not `.env.production.example`.** The `.env*` PreToolUse hook (session 02) blocks the file. The hook itself recommends `07-INFRA.md`, which already housed the secrets inventory — adding a "Production .env template" section there keeps related material together and respects the existing security boundary.
4. **No new ADR.** Adding Nginx as reverse proxy and systemd as backend supervisor are operational glue, not architectural choices that change the stack. ADR-0011 covers Bun + Node; the deploy mechanism is implementation detail. ADR-0008 was already amended in session 06 for the GraphHopper specifics that affect deploy.
5. **DO API integration deferred.** The harness blocked both `curl api.digitalocean.com` and `update-config` (cited self-modification). Eduardo's recommended path was manual SSH anyway; API automation is post-M1 if at all.
