## Decisions Made

1. **Dump-first corrigiu: o trigger do Reotimizar é o KEBAB, não o toolbar.** O B1 registrara (errado) que o trigger vivia no OrderStopGroups/toolbar. O jadx provou a cadeia real: kebab `more_options_reoptimize_route_title` → `ReoptimizeActiveRoute` → `ShowReoptimizeRouteDialog` → `ReoptimizeRouteDialog`. O `OrderStopGroupsOptimizeButtonType.Reoptimize` é outra coisa (PR-D). Logo o wire kebab→`ReoptimizeOptionsSheet` coube no B2.
2. **Dump-first corrigiu: o marker mostra endereço/id, NÃO o chip A1.** O `StopMarkerLabel` do Spoke = endereço + hora; o chip A1..AN é exclusivo da lista. Sem o dump, eu teria posto o chip no pino (parecia óbvio).
3. **Markers via `BitmapDescriptor` desenhado em `dart:ui` Canvas, SEM pacote** (Q1). Context7 (`/flutter/website`) confirmou o pipeline `Canvas`→`toImage`→`toByteData(png)` + que `fromBytes` está deprecado (usar `.bytes`). Decisão tomada por mim (default técnico claro), não perguntada.
4. **Marker NÃO mostra hora estimada** (Q3) — o solver local NN+2-opt dá tempo geométrico grosseiro; "hora" derivada dele seria número falso que engana. ETA real é Slice 3. Eduardo delegou "boas práticas / evite disparidade" → a leitura correta é não exibir número falso (a paridade com o Spoke é estrutural; o Spoke tem hora porque tem backend).

## Bugs/achados pegos pelos gates e revisões (e tratados)

1. **Perf must-fix (perf-auditor):** o `routeMapMarkersProvider` regerava TODOS os bitmaps do zero a cada reotimização (cache local perdido na invalidação) → 30 PNGs sequenciais no UI thread em rota grande. FIX: `StopMarkerBitmapCache` `keepAlive` (cache por label sobrevive) + `Future.wait` (paralelo). Commit `aed06a4`.
2. **Spoke-parity must-fix (D4):** os markers apareciam no DRAFT (sem gate), divergindo do Spoke (que só mostra pinos na rota otimizada). FIX: gate `isPreConfirm` idêntico ao da polyline. + 3 ícones Material → Lucide. Commit `45bbb0e`.
3. **Vazamento `dart:ui` (auto-revisão da T3):** o `stopMarkerBitmap` não fazia dispose de `picture`/`image`/`paragraph` (handles nativos não-GC'd) → vazamento por marker. FIX: try/finally aninhado. Commit `01b12c0`.
4. **Drift de API (T3):** `BitmapDescriptor.fromBytes` está deprecado na versão instalada (2.17.1) → o implementer verificou e usou `.bytes`. Exatamente o drift pós-cutoff que a precedência Dart-MCP/Context7 existe para pegar.
5. **Drift de API (T5):** `.valueOrNull` não existe nessa versão do Riverpod → `.value` (idiom do projeto). Pego no analyze inline.
6. **Nits do completeness-critic (workflow):** `bytes!` força-unwrap → erro observável (`StateError` em vez de crash mudo); comentário do invariante de cor do cache (se cor-por-parada entrar, estender a chave); comentário de baseline dump-first na microcopy. Commit dos 3.
