## Como usar esta tabela

- **O dump diz O QUÊ existe** (verdade congelada): textos PT-BR exatos com seus `name=` de recurso, quais campos cada tela tem, defaults (08:00–15:00, 30 min), ranges/validações, enums de opções, a árvore de telas.
- **O runtime diz COMO se comporta** (verdade viva): qual tela um toque realmente abre, ordem da back-stack, animações de sheet, estados desabilitados pós-otimização.
- **Ordem correta:** dump PRIMEIRO (monta a tabela de fatos + hipóteses concretas com texto exato), runtime SÓ DEPOIS para CONFIRMAR cada linha. Cada linha carrega o campo **Precisa-runtime** com exatamente o que ainda precisa de um clique ao vivo para virar fato. Quando o campo está vazio ou diz "Nenhum", a linha já é fato e pode ser implementada sem clicar no Spoke.

**Legenda de Confiança:** `high` = código + strings + (quando aplicável) screenshot concordam; estrutura clara no decompilado. `medium` = strings presentes e pacote localizado, mas defaults/ranges ou ramo de UI inferidos do código obfuscado. `low` = só strings + nome de pacote; estrutura interna não confirmada.

## Achados que contradizem ou enriquecem o inventário atual

O inventário canônico (`docs/inventory/2026-05-26-spoke-vs-rotpro.md`) foi montado em grande parte por **paráfrase** de inspeção runtime, antes deste dump estático. Onde o dump revelou algo que a paráfrase não tinha — ou tinha de forma diferente — registro aqui, do mais relevante ao menos.

### 1. `break_detail_sheet` (Pausa) — o dump CONFIRMA tarde o que o ADR-0044 já corrigiu, e reforça que a paráfrase original estava errada

O ADR-0044 (2026-06-09) já tinha corrigido a Pausa **via inspeção runtime** (Maestro MCP no M54): a Pausa é uma **página full-screen** "Configure a pausa", e `BreakConfig` é uma **janela de tempo** (`fromTime`/`toTime`, default 08:00–15:00) + duração inteira de minutos (default 30) — NÃO um `startTime` único nem chips 15/30/60. Este dump estático **corrobora** esse achado por uma via independente (decompilado, não runtime):

- O pacote `com/circuit/ui/home/editroute/components/detailsheet/breaks` existe na árvore (`ui-screen-tree.txt` linha 38) — a Pausa tem seu próprio sub-pacote de componentes, consistente com uma surface dedicada, não um campo qualquer dentro de outro sheet.
- A string `break_duration_dialog_title` = **"Duração da pausa (minutos)"** está no dump (gap #7) — confirma o **AlertDialog de minutos livres** descrito no ADR-0044 §"duração", e desmente diretamente a antiga inferência de "chips 15/30/60" que estava no plano `slice2-completion.md` §MS-A5.6.
- O campo de duração inteira (`ur0.f136175d` = duração em minutos) bate com `durationMinutes: int` (default 30).

**O que o ADR-0044 NÃO cobriu e este dump enriquece:** o gap **#7 ("Tempo estimado na parada", `stop_property_time_at_stop`)** é uma coisa DIFERENTE da duração da Pausa, apesar de o agente tê-los agrupado na mesma linha. "Tempo estimado na parada" é um campo **por-parada** dentro do StopDetailSheet (Área 6), cujo default vem do **setting global** "Tempo médio na parada" (Área 10, roadmap linha 187: "1/2/3/5/10/custom — alimenta default da Área 6"). A "Duração da pausa" é um campo **da Pausa** (Área 5). O dump misturou os dois sob `breaks` porque o pacote `breaks` referencia ambos os títulos; **na implementação RotPro eles vivem em telas diferentes e têm defaults de origens diferentes.** Trate-os como dois campos distintos, não um.

### 2. Destino (#14) — o dump fixa a ORDEM e os SUBTÍTULOS exatos das 3 opções (o ADR-0043 tinha o conceito; o dump tem o texto)

O ADR-0043 já estabeleceu o sheet de 3 cards para o Destino via runtime. O dump adiciona o que faltava de **verbatim e ordem**: as 3 opções são, nesta ordem, (1) "Voltar ao ponto de partida" / "Ida e volta (recomendado)", (2) "Destino em outro endereço" / "Digite qualquer endereço", (3) "Não usar destino" / **"Não recomendado para transportadoras"**. O subtítulo da opção 3 é uma confirmação B2C importante: o "transportadoras" aqui é o motorista-entregador, não uma frota Dispatch — alinha com a fronteira B2C de MEMORY (`project_spoke_b2c_vs_b2b_boundary`). Ainda assim, `Precisa-runtime`: confirmar a ordem no modal e se é dismissível ao tocar fora.

### 3. Partida / Iniciar agora / Término (#12, #13, #15) — confiança `high` com linhas de código, sem `Precisa-runtime` bloqueante

Estas três linhas do Route Setup decompilaram **excepcionalmente legíveis** (métodos `m10035h`, `m10039J` com ranges de linha, `RouteSetupFragment.onViewCreated` linha 147). O #12 (Partida) tem `Precisa-runtime: Nenhum`. Isso significa que a Área 5 (que o ADR-0044 fechou na parte de Pausa) tem agora baseline de fato para os campos Início/Término também — **o default "Iniciar agora mesmo" quando null, e o picker abrindo na hora atual do sistema, são fatos do código**, não inferências. O único `Precisa-runtime` real e acionável é se o picker de **Término força `end_time > start_time`** (#15) — uma validação que o RotPro precisa decidir replicar ou não.

### 4. "Localizador de pacotes" (#5) é a única linha `low` — não implementar sem clicar no Spoke

Tudo que o dump tem de #5 são duas strings (`package_finder_title`, `locate_packages_with_package_finder`) e o nome do pacote `dialogs/packagedetails`. A estrutura da lista, os atributos de cada pacote, e se há busca/filtro são **desconhecidos**. O inventário tratava "Localizador de pacotes" como um campo do edit-stop (Área 6 roadmap linha 154), mas o dump não consegue confirmar nem a forma do widget. **Esta é a candidata #1 a uma inspeção runtime dedicada antes de qualquer código** — ou a um corte explícito, já que "Localizador de pacotes" pode ser uma feature B2B-adjacent (organização de muitos pacotes por parada) de baixo valor para o entregador B2C brasileiro.

### 5. Remover parada (#10) — texto de confirmação NÃO está no dump

O dump tem `delete_stop_action_title` = "Remover parada" e o ícone `delete_outline`, mas o **texto do diálogo de confirmação** ("Quer mesmo remover…?") não foi encontrado para a parada individual. Contraste com #24 (Remover paradas em massa), onde os textos de confirmação (`remove_all_stops_confirm_description` etc.) **estão** no dump. O roadmap (linha 154) já assume "AlertDialog confirm" para Remover parada — o dump confirma que existe um confirm, mas o texto exato precisa de runtime ou pode ser microcopy original RotPro (que é o esperado per ADR-0035 de qualquer forma).

### 6. Kebab da Edit Route tem MAIS itens do que o roadmap lista — e vários são CORTADOS

O dump revela o menu kebab completo da edit route: Compartilhar cópia (#17), Transferir paradas (#18), Copiar paradas (#19), Pular otimização (#20), Imprimir rota (#23), Remover paradas (#24). O roadmap (Área 9, linha 181) já corta **"Compartilhar cópia da rota" e "Transferir paradas"** como B2B-adjacent. O dump **confirma a semântica** que motivou o corte: `share_route_alert_message` = "Compartilhe uma cópia desta rota com **outros usuários do Spoke**" (transfer peer-to-peer entre motoristas) e `transfer_stops_receive_details` = "Leia o **QR code** para assumir paradas" (handoff de paradas entre motoristas) — ambos são fluxos de coordenação multi-motorista, claramente Dispatch-adjacent. Isso **resolve o §13.C.5 PENDENTE** (roadmap linha 260, "Compartilhar cópia vs Transferir") em nível de evidência: as duas são peer-transfer, não compartilhamento com cliente final, e o corte está correto. **"Imprimir rota" (#23)** é um item novo que o roadmap não menciona explicitamente — é baixo esforço (Android print framework) mas baixa prioridade B2C.
