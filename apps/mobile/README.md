# apps/mobile — Roteirizador Pro (Flutter)

Android-only Flutter app. M1 ships Login + Register. M2 ships the rest of the 19 prototype screens.

## Bootstrap (one-time, after cloning)

This folder ships the source-controlled files (pubspec, analysis_options, lib/, .env.example) but **not** the platform-specific Android folder. You must generate the Android project locally with `flutter create` once.

### Prerequisites

- Flutter SDK ≥ 3.24 (stable channel) — install via [flutter.dev/install](https://docs.flutter.dev/get-started/install).
- Android SDK + emulator (or a physical device with USB debugging enabled).

### Steps

```bash
# 1. From this folder (apps/mobile/), generate the Android platform project.
#    --no-pub skips the implicit pub get; we run it explicitly afterwards.
#    --org sets the application package prefix (br.com.roteirizadorpro).
#    --project-name forces the package name to roteirizador_pro (matches pubspec.yaml).
flutter create --platforms=android --org br.com.roteirizadorpro --project-name roteirizador_pro --no-pub .

# 2. Resolve dependencies.
flutter pub get

# 3. Smoke run on Android emulator.
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:3000 --dart-define=APP_ENV=development
```

`flutter create .` is safe in a non-empty directory — it skips files that already exist (so it will not overwrite our `pubspec.yaml`, `lib/`, or `analysis_options.yaml`).

## Environment variables

Flutter does not read `.env` files at runtime. Pass values via `--dart-define` (see `.env.example` for the full list and example commands). Read them in code via `String.fromEnvironment(...)` — see `lib/core/env/app_env.dart`.

## Project layout

```
apps/mobile/
├── pubspec.yaml             # deps + project metadata (versioned)
├── analysis_options.yaml    # linter (versioned)
├── .env.example             # documents --dart-define values (versioned)
├── lib/                     # all Dart source (versioned)
│   ├── main.dart
│   ├── app.dart             # MaterialApp.router + GoRouter config
│   ├── core/
│   │   ├── env/             # --dart-define readers
│   │   └── theme/           # AppColors + AppTheme (mirrors prototipo/tokens.js)
│   └── features/
│       └── placeholder/     # phase 1 stub — replaced by auth in phase 2
├── android/                 # generated by flutter create (gitignored partially)
└── test/                    # generated by flutter create
```

## Code conventions

- All providers live under `lib/state/` once introduced (see ADR-0005).
- Use class-based `Notifier` / `AsyncNotifier` (Riverpod 3 pattern), never the old function-based syntax.
- Run `flutter pub run build_runner watch --delete-conflicting-outputs` during development to regenerate `*.g.dart` files for `@riverpod`-annotated providers.
- Generated files (`*.g.dart`, `*.freezed.dart`) are gitignored — never commit them.
