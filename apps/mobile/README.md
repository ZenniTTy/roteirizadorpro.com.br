# apps/mobile — Roteirizador Pro (Flutter)

Android-only Flutter app. M1 ships Login + Register. M2 ships the rest of the 19 prototype screens.

## Prerequisites (already satisfied on this machine)

- Flutter SDK ≥ 3.41 (stable channel) — `brew install --cask flutter`.
- Android Studio + Android SDK + an emulator AVD — `brew install --cask android-studio`, then run the SDK Manager once.
- VS Code with the official Flutter and Dart extensions.

## Daily dev loop

The repo is past first-time setup (the Android platform project, `pubspec.lock`, and a working AVD already exist), so the loop is short:

```bash
# 1. Make sure the emulator is up. From the project root:
~/Library/Android/sdk/emulator/emulator -avd Pixel_8 &

# 2. Run the app from this folder.
cd apps/mobile
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:3000 --dart-define=APP_ENV=development
```

Once `flutter run` is attached, **stay attached**:

| Change | Action | Cost |
|---|---|---|
| Edit anything in `lib/**` (widget, color, copy, method body) | Press `r` in the terminal — or save the file in VS Code with the Dart extension active (auto hot reload via `dart.flutterHotReloadOnSave: always`) | sub-second, preserves state |
| New top-level provider, new route, change to `main()` | Press `R` for hot restart | ~2 s, loses state |
| `pubspec.yaml` asset/dep change, native code change, AndroidManifest change | `q` to quit, then re-run `flutter run` | 2–7 min |

Do **not** kill `flutter run` for trivial edits. ADR-0012 codifies this rule.

## Codegen watcher

When we start using `@riverpod` codegen (Phase 2 mobile), open a second terminal:

```bash
cd apps/mobile
dart run build_runner watch --delete-conflicting-outputs
```

It rebuilds `*.g.dart` whenever you save an annotated file. Leave it running alongside `flutter run`.

## First-time bootstrap (only relevant on a fresh machine)

If you cloned the repo onto a new machine that does not yet have the Android platform project generated:

```bash
flutter create --platforms=android --org br.com.roteirizadorpro --project-name roteirizador_pro --no-pub .
flutter pub get
```

`flutter create .` is safe in a non-empty directory — it skips files that already exist (so it will not overwrite our `pubspec.yaml`, `lib/`, or `analysis_options.yaml`).

## Environment variables

Flutter does not read `.env` files at runtime. Pass values via `--dart-define` (see `.env.example` for the full list and example commands). Read them in code via `String.fromEnvironment(...)` — see `lib/core/env/app_env.dart`.

## Code conventions

- File and folder names follow Effective Dart: `lowercase_with_underscores.dart`.
- All providers live under `lib/state/` once introduced (see ADR-0005).
- Use class-based `Notifier` / `AsyncNotifier` (Riverpod 3 pattern), never the old function-based syntax.
- Run `dart run build_runner watch --delete-conflicting-outputs` during development to regenerate `*.g.dart` files for `@riverpod`-annotated providers.
- Generated files (`*.g.dart`, `*.freezed.dart`) are gitignored — never commit them.
- The Lefthook pre-commit hook runs `flutter analyze --no-pub` automatically when staged files include `apps/mobile/**/*.dart` (per ADR-0012 / `lefthook.yml`).
